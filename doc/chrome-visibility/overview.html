Agent Chrome Map

A framework so that every agent on the MacBook uses Chrome properly: it answers 5 questions for each agent: may it open a tab, with which profile, headless or not, in which window, and without taking focus.

exists prototyped & tested to build to investigate

Out of scope: alerts and notifications to you. Each agent decides whether to open a task for you and whether to alert you; this framework only gives it the facts.

What goes wrong today
Windows nobody explainsA tab says nothing about which session opened it, when, or for which project. You close them by hand (LinkedIn, 1 Nov: 2–3 windows from 3 auto-job-apply runs).
"Your turn" is invisibleWhen an agent waits for you (captcha, file upload, login), the page itself shows nothing.
Agents don't know what is already openEach run opens a new window instead of reusing the one its project already has. A job retried 3 times leaves 3 windows.
Rules are only textHeadless by default, right profile, close every tab: written in CLAUDE.md and skills, enforced almost nowhere.
Window checks go blindWith two Chromes running, macOS window scripts see 0 windows and still report "closed (checked)".
Windows jump to the frontVisible agent windows can come forward and take the focus while you type elsewhere.
Target design

One Chrome kit in my-setup, every agent goes through it

How it is stored, and why

Two files: what is open now, and the history

QuestionWho asksHow oftenAnswered fromSpeed
What is open for my project right now? Reuse it or open a new one?every agent, before opening a tabdozens / dayopen.json (a few dozen entries, a few kB)< 1 ms read
Who opened this tab, when, for which project?the bar on the tabevery page loadopen.json< 1 ms
Which tabs and Chromes are open now, by whom?you (chrome-who), chrome-leftoversa few / weekopen.json + running Chrome processes~ 50 ms
What did project X open last week, and why?yourarehistory/<month>.jsonl~ 10 ms per month

One file per project would not be faster: the "open now" file stays tiny, and Python's start (~28 ms) costs more than reading it. One small file has one lock and one place to look. The "open now" file can drift from reality (you close a tab, Chrome restarts), so every Claude in Chrome answer, which lists the real open tabs, corrects it, and entries older than the browser's start are dropped.

The 5 questions

What every agent answers before using Chrome

1 · May it open a tab?

security
  • 1aA reason firstThe hook refuses to open a page until the agent ran chrome-claim --purpose "…"; a scheduled job sets it in its environment.done
  • 1bNo Chrome started from the shellThe hook refuses a visible Chrome launched from a terminal command: a window nobody tracks.done
  • 1cAllowed sites per project (optional)A project may declare which sites its agents may open. job-applications already has its own list; the kit would let any project declare one.later

2 · Which profile?

security
  • 2aEach profile belongs to its projectsClaude - LinkedIn → job-applications only · Claude - Facebook → marketplace-seller only · Claude - general → any project. Enforced by the hook.done
  • 2bNever your profileYour Default profile (Bitwarden) is refused, by the hook and by the file rules.done
  • 2cOne profile per sessionOnce a session picked a profile it can't switch: an honest agent reaches LinkedIn or a general site, never both in one session.being built
  • 2dLimit: a malicious agentProfiles stop honest mistakes, not an agent that bypasses hooks through the shell. What protects you there: no vault in any agent profile, each job's secrets in its own ~/.config/<agent>/.stated

3 · Headless, invisible?

your comfort
  • 3aHeadless by defaultScripts start Chrome only through the kit's launcher: marketplace-seller, robotics-radar, smart-home tests; the password layer is recorded and watched.done
  • 3bVisible only with a stated reasonA Claude in Chrome tab (always visible) needs --needs-human "what you must do" or --visible-because "why headless can't".done
  • 3cA killed script never leaves Chrome runningA watchdog quits the launcher's Chrome when the script that started it dies (a job timeout leaves it today).being built
  • 3dScheduled jobs on logged-in sites go headlessPrefer a headless Chrome with its own data folder, logged in once by you (as marketplace-seller does), over a visible profile.to discuss

4 · If visible: which window?

your comfort
  • 4aAsk what is open firstchrome-claim open: the tabs open for my project, by any session or job; one tab per session.done
  • 4bA job never piles up windowsauto-job-apply closes its old tab nobody waits on, and never opens a second tab for a job still waiting on you.done
  • 4cOne agent window per projectEvery session of a project puts its tab in that project's agent window; a new window only if none exists. Your own windows are never touched. Being tested: can Claude in Chrome put a session's tabs in an existing window?being tested

5 · If visible: focus?

your comfort
  • 5aNever take focusAn agent window opens and works in the background, never in front of what you are typing.being tested
  • 5bOn the project's desktopEach project's agent window lives on that project's macOS desktop (you have 4). Being tested: Hammerspoon moving a window to a desktop.being tested
  • 5cThe kit opens a missing profile itselfIn the background, on the right desktop, instead of asking you; replaces the job-applications-only exception.being tested

Who opened what

for you and for agents
  • W1Every tab carries its factsOpened at, the Claude session's UUID, the project (+ the job), the reason, "YOUR TURN: …" in red. 30 px bar that pushes the page down; badge ! / AI / ✓; quiet on LinkedIn and Facebook unless you must act.builtyour "Load unpacked" pending
  • W2Recorded without the agent's goodwillThe hook records every open, navigation and close (also tabs you close); scheduled jobs and scripts too.done
  • W3You ask: chrome-whoEvery open agent tab and Chrome; --since 7d for the history; BLIND when two Chromes confuse macOS scripts.done

Talking to the agent

from the tab
  • C1Comment box in the side panelYour message reaches the session that opened the tab at its next step; it answers on the tab. Claude in Chrome's own chat was ruled out: it talks to a separate Claude.built
  • C2Reach an idle or ended sessionIdle: type into its tmux pane safely. Ended: the tab shows how to resume it.later

Cleanup

nothing left behind
  • K1End-of-turn reminderA tab left open with nobody waiting: the session is asked once to close it or say what you must do.done
  • K2chrome-leftovers starts from the recordWho opened each leftover and why; old transcripts only for what has no record.done
  • K3Kept tabs expireA tab kept for you closes after a deadline (auto-job-apply: 2 h); the kit would do it for every project.later
